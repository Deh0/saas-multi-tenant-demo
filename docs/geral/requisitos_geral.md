# Requisitos e Funcionalidades 

Será destacado neste tópico todos os requisitos que o projeto terá, tanto para o e-commerce, quanto para o sistema de gestão, sendo separado por subtópicos. O objetivo é descrever as funcionalidades e o que o projeto deve ter para conseguir dar os resultados desejáveis. 
Será separado por requisito funcional, requisito não funcional. Os requisitos funcionais tem como função descrever todas as funcionalidades do sistema, então tudo que o sistema deve fazer deverá ser descrito nesta categoria. Os requisitos não funcionais tem como missão analisar como o sistema se comporta em um todo. Os exemplos práticos são desempenho, segurança, disponibilidade, escalabilidade e usabilidade. Então tudo aquilo que for direcionado a esses exemplos serão destacados como requisito não funcional. 
Para ter um bom entendimento, palavras chaves: RF: "Requisito Funcional". RNF: "Requisito Não Funcional". 

Os requisitos de um sistema são a primeira parte a ser feita e levantada em um desenvolvimento de software. Porque sem ele é como se estivesse programando as cegas, como se a sua mente fosse a documentação. 
Sabe qual é o problema disso? Nossa mente esquece, é falha, ou deixa escapar algumas informações que no futuro a gente descobre que precisava. 

### O que conseguimos entender disso?

Quando pensamos em desenvolver um sistema, pensamos no que ele poderá fazer? Ou o que ele precisa ter? Ou o que deve ser feito? E assim por diante. Essas perguntas nós ajudam a descobrir o porquê o nosso sistema serve e se ele vai ser realmete útil. 
Exatamente ai vem o levantamento dos requisitos, das funcionalidades, das restrições, dos atributos, das entidades e dos relacionamentos do sistema. Tudo o que precisamos para a criação da [Diagramação](diagramacao.md) e [Modelagem](modelagem.md)
